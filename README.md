# cgui

ローカルで動く、ファイルを「見る・書き換える」ためのGUI。Claude Code と git の操作は CLI に任せ、GUI と CLI はプロジェクトのファイルだけでつながる。設計は [DESIGN.md](./DESIGN.md)、画面の検討用プロトタイプは [prototype.html](./prototype.html)。

CLI がローカルサーバーを立て、ブラウザで画面を開く。WSL なら、Windows 側の Chrome / Edge を専用ウィンドウ（`--app`）で開く。

## 今できること（最小構成）

- `cgui .` でフォルダをプロジェクトとして開く。すでに動いていれば、そのサーバーにタブを足す
- ファイル一覧（フォルダの移動、選択位置の記憶）と、プレビュー（MD、コード、画像）
- 表示に対応していないファイル（テキストではないもの）は、プレビューで知らせる
- CLI がファイルを書き換えたら、監視して画面に反映する

まだないもの: 編集と保存、ブックマーク、プレビューのタブ、Git の差分、Mermaid（DESIGN.md を参照）。

## 導入

WSL2（Ubuntu など）で使う前提で書いている。macOS や Linux でも同じ手順で入る。

### 1. 必要なもの

- WSL2。プロジェクトは WSL 側（`/home/...`）に置く。`/mnt/c/...` に置くと、ファイルの変更を検知できない
- Node 20 以上（WSL の中に入れる。Windows 側に入れたものは使えない）
- `git`（Ubuntu の WSL なら最初から入っていることが多い。なければ `sudo apt install git`）
- Windows 側のブラウザ（Chrome か Edge があれば、専用のウィンドウで開く）

Node が入っていなければ、nvm で入れる。

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# ターミナルを開き直してから
nvm install --lts
node -v   # v20 以上なら OK
```

### 2. cgui を入れる

```bash
# 公開後
npm i -g github:kokuto821/gui-editor

# 非公開のうち（GitHub に SSH 鍵を登録し、リポジトリを読めること）
npm i -g git+ssh://git@github.com/kokuto821/gui-editor.git
```

入れるときに画面のビルドが走るので、少し時間がかかる。版を決めて入れるときは、末尾に `#v0.1.0` のようにタグを付ける。

```bash
cgui --help   # 説明が出れば、入っている
```

### 3. 更新と削除

```bash
npm i -g github:kokuto821/gui-editor   # 更新（同じコマンドをもう一度）
cgui stop                              # 動いているサーバーを止める（更新の後は、止めてから開き直す）
npm rm -g cgui                         # 削除
```

### うまく動かないとき

| 症状 | 確認すること |
| --- | --- |
| ブラウザが開かない | 表示された URL（`http://127.0.0.1:...`）を、Windows のブラウザに貼る。`CGUI_BROWSER` に使いたいブラウザの実行ファイルを指定してもよい |
| 画面が開くが「接続が切れています」と出る | `cgui stop` のあと、もう一度 `cgui .` を実行する。ログは `~/.cache/cgui/server.log` |
| 変更が画面に反映されない | プロジェクトが `/mnt/c/...` にないか確認する。WSL 側（`/home/...`）に置く |
| `npm i -g` で権限のエラーが出る | `sudo` は使わず、nvm で入れた Node を使う（上の手順） |

## 使い方

### 起動と終了

```bash
cgui .              # 今のフォルダをプロジェクトとして開く
cgui ~/work/blog    # フォルダを指定して開く
cgui stop           # サーバーを止める
cgui --no-open .    # ブラウザを開かず、URL だけ表示する
```

- 別のフォルダでもう一度 `cgui` を実行すると、動いているサーバーにタブが増える。画面がすでに開いていれば、ブラウザは開き直さない。
- ターミナルは、すぐに使える状態に戻る（サーバーは背景で動き続ける）。
- プロジェクトのタブを閉じても、サーバーは止まらない。止めるときは `cgui stop`。

### 画面

```
┌─[proj]─[blog]──────────────────────────────┐  プロジェクトのタブ
├────────────────┬───────────────────────────┤
│ ▸ docs/        │  プレビュー                  │  左: ファイル一覧
│ ▸ src/         │  （MD・コード・画像）         │  右: 選んだファイルの中身
│ PLAN.md        │                           │
├────────────────┴───────────────────────────┤
│ proj · ~/work/proj / PLAN.md               │  ステータスバー
└────────────────────────────────────────────┘
```

- 一覧でカーソルを動かすたびに、プレビューが替わる。
- `.md` は整形して表示する。` ``` ` のコード、表、チェックボックス、画像（相対パス）も出る。MD の中の相対リンクを押すと、そのファイルへ移る。
- コードは行番号付きで表示する。画像は `png` `jpg` `gif` `webp` `svg` を表示する。
- テキストではないファイルや大きすぎるファイルは、プレビューに「表示に対応していません」と出る。
- CLI（Claude Code など）がファイルを変えると、自動で反映される。

### キー操作

| 操作 | キー |
| --- | --- |
| 上下に移動 | `↑` `↓` / `j` `k` |
| 親のフォルダへ | `←` / `h`（ホームより上には行けない。ホームの外のプロジェクトは、そのフォルダまで） |
| フォルダの中へ | `→` / `l`（ファイルの上では何もしない） |
| 先頭 / 末尾へ | `g` / `G`（`Home` / `End`） |
| プレビューをスクロール | `d` `u`（半ページ） |
| プロジェクトを切り替える | `Alt+1` 〜 `Alt+9` |
| プロジェクトを閉じる | `Alt+W` |

- 一覧のファイルをマウスで選んでもよい。フォルダはダブルクリックで中へ入る。
- プレビューをクリックすると、キー操作の対象がプレビューに移る。`↑` `↓` / `j` `k` で少しずつ、`d` `u` で半ページ、`g` `G` で先頭 / 末尾へ動く。`Esc` で一覧に戻る。
- ブラウザの `Ctrl+T` などは奪えないため、プロジェクトの操作は `Alt` 系にしている。

### 設定とファイルの場所

| もの | 場所 |
| --- | --- |
| サーバーの情報（ポートとトークン） | `~/.cache/cgui/lock.json` |
| サーバーのログ | `~/.cache/cgui/server.log` |
| ブラウザの指定 | 環境変数 `CGUI_BROWSER` |

- サーバーは `127.0.0.1` だけで待ち受ける。URL のトークンと `Host` / `Origin` を確かめるので、ほかのマシンや、開いている別のサイトからは使えない。
- 読めるのは、ホームと、開いているプロジェクトのフォルダの下だけ。

## 開発

```bash
npm install
npm run build      # 画面（dist/web）とサーバー（dist/cli.js）を作る
npm link           # cgui コマンドを、このフォルダへのリンクにする
npm test           # vitest
npm run typecheck
npm run dev:web    # 画面だけを Vite で動かす（サーバーは別に要る）
```

構成は DESIGN.md の6章「内部構成」を参照。
